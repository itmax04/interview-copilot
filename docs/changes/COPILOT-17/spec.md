# COPILOT-17: Spec

ID: COPILOT-17-spec · Status: **draft** (for the owner's review) · Version: 1 · Date: 2026-11-23
Links: [intent.md](intent.md), [plan.md](plan.md), [handoff.md](handoff.md)

## Starting point
Branch `feat/copilot-17-uk-question`, cut from `feat/copilot-16-source-language` at 50e65b6 (COPILOT-16 is not merged into
`main`). FluidAudio 0.17.7: `AsrManager.transcribe(_:decoderState:language:)` — `language:` is a **script filter only**
(`TokenLanguageFilter.swift:28-48`); Ukrainian and Russian are both Cyrillic, so the hint removes Latin (and other-script)
tokens but does **not** separate uk from ru.

Existing pieces reused: `QuestionRedecoder.Config.waitsForWhisper` / `StreamingTranscriber.Config.hintWaitsForWhisper`
(COPILOT-15, off, never wired to a setting), `StreamingTranscriber.onHistoryText` (Whisper result per turn, history only),
`ActiveTopic` (`rootQuestion`, `rootTitle`), `AnswerEntry.rootTitle`, `SessionStore.deleteAll`, `AppPaths`.

## Requirements
| ID | Requirement |
|---|---|
| R-01 | **Parakeet language hint.** `ParakeetEngine.transcribe` maps its `language` argument to FluidAudio's `Language` and passes `language:` when the session language is fixed: `uk → .ukrainian`, `ru → .russian`, `en → .english`. For `auto` (and any unmapped value) it passes nothing, as today. The mapping is a small pure function in CopilotCore (unit-testable without the model). The same engine instance serves the owner's microphone transcriber, so the hint follows that transcriber's language too |
| R-02 | **Known trade-off of R-01, made visible.** The script filter blocks Latin tokens for uk/ru, so English terms inside a Ukrainian/Russian phrase («Docker», «REST») may come out transliterated or dropped. Mitigation: the existing term handling stays; the effect is measured (AC-02) and listed in the handoff; the language-hint can be switched off by one constant/setting-free flag `ParakeetEngine.useLanguageHint` if H-1 shows a regression (executor decision recorded in the handoff). Interaction with COPILOT-16: an English phrase that Parakeet can no longer emit as Latin reaches `LanguageGate` as Cyrillic noise instead of English — checked in AC-02 |
| R-03 | **New-ticket openers.** `FollowUpDetector.isExamFollowUp` returns false (new ticket) when the question **starts** (after trimming punctuation, case-insensitive) with an opener: uk `назвіть`, `перелічіть`, `охарактеризуйте`, `розкрийте`, `що таке`, `що називається`, `дайте характеристику`; ru `назовите`, `перечислите`, `охарактеризуйте`, `раскройте`, `что такое`, `что называется`, `дайте характеристику`; en `what is`, `what are`, `name the`, `define`, `describe`, `explain`. The openers are start-anchored (a «що таке» in the middle of a follow-up such as «а що таке це в цьому випадку» does not start a ticket). The existing markers (`topicShiftMarkers`, `newTicketMarkers`) and the ≤ 8-word rule for other short questions stay. The final list is fixed in P-03 against the synthetic cases of R-04, not by taste |
| R-04 | **Eval cases for R-03.** A synthetic dataset `evals/exam-followup/cases.jsonl` (≥ 24 new-ticket phrases uk/ru/en with each opener, ≥ 24 real follow-ups: «яка стаття ця?», «а в цьому випадку?», «чому саме так», anaphoric and ≤ 8-word clarifications) and a `copilot-eval` subcommand or `run-evals.sh` line that reports correct/total. No real transcript text; sentences are invented and generic |
| R-05 | **Whisper corrects the ticket root.** When `onHistoryText` delivers the Whisper text for a turn that is the **root of the active ticket** (`ActiveTopic.rootExchangeID`/`rootEntryID` match, root text still equals the text that was shown), `ActiveTopic.rootQuestion` and `rootTitle` are replaced with the Whisper text (title via `AnswerHistory.title(for:)`), the root entry title and the `rootTitle` of its follow-up entries in `AnswerHistory`/`PanelModel` are updated, and the `InterviewMemory` exchange text is updated (as today for history). Guards: the Whisper text is non-empty, passes the existing hallucination check, is not the same text, and the ticket has not changed in the meantime (race: the root moved on → ignore). No hint is regenerated and no hint latency is added. Log once per update: `ticket_root_updated turn=… chars_old=… chars_new=…` (numbers only) |
| R-06 | **Setting «Точный вопрос (+2 с)».** New `AppSettings` field `preciseQuestion` (three states: `auto` — default, `on`, `off`; decoded with `decodeIfPresent`, old files load). Effective value: `on` → wait; `off` → no wait; `auto` → wait only for an **exam** session (`SessionType.exam`). In every case the wait is applied **only when the session language is `uk`** (ru, en and auto sessions never wait). The effective value sets `StreamingTranscriber.Config.hintWaitsForWhisper` when the session starts; it cannot change mid-session. UI: a row in Settings → Recognition with a short explanation («Подсказка ждёт повторное распознавание Whisper: текст вопроса точнее, первый токен позже ≈ на 2 с. Только для украинского»). Russian string in code as one literal, English in `Resources/en.lproj/Localizable.strings`; `IC` tokens only |
| R-07 | **Wait behavior and failure modes.** With the wait on, the hint starts from the Whisper text; if Whisper does not return within the existing `QuestionRedecoder.whisperBudget`, the hint starts from the Parakeet text exactly as without the wait (no stall, no error). Log per question: `hint_wait_whisper waited_ms=… used=whisper|parakeet`. The wait does not apply to speculative drafts or to bank cards |
| R-08 | **No other latency change.** R-01 adds no model pass and no audio copy; R-03 and R-05 are string logic on the final text. Budgets are in AC-03/AC-06 |
| R-09 | **Opt-in local question-audio saving.** New `AppSettings` fields `saveQuestionAudio` (Bool, **default false**) and `questionAudioRetentionDays` (default 14; allowed 1…90, clamped in `normalized()`). When on, for each recognized **call-channel** question turn the 16 kHz mono audio of the question range (the range `QuestionAudioRange` already extracts for the redecode) is written as a 16-bit PCM WAV to `AppPaths.root/question-audio/<session-start>-<turn>.wav`, plus a sidecar `….json` with **numbers only** (duration, sample rate, session language, engine and Whisper durations, channel, whether the Whisper text differed). **No transcript text in the sidecar or the file name** (the text lives only in the session JSON as today). Directory 700, files 600, excluded from backup (`isExcludedFromBackup`). Never under the repo, never in logs (log only `question_audio_saved bytes=… seconds=…`). Owner microphone audio is **not** saved (only the interviewer's call channel). Writing happens off the real-time path (background queue, after the turn is delivered), failure is logged and ignored. Settings row with plain wording: «Сохранять аудио вопросов на этом Mac» + a one-line note that it stores other people's voices and is deleted automatically after N days |
| R-10 | **Retention and wiping.** On app start and at session end, files older than `questionAudioRetentionDays` are deleted (also when saving is switched off — old files are still purged). «Удалить всю историю» (`SessionController.deleteAll` → `SessionStore.deleteAll`) also removes the whole `question-audio/` folder, including unreadable files. A separate button «Удалить сохранённое аудио» appears next to the setting, with a confirmation. Turning the setting off does not delete files by itself (the owner may still want the bake-off set) but the settings row shows the current count and size |
| R-11 | **Documents.** `AGENTS.md` (the statements «No audio is ever written to disk» in §1 and any similar sentence are updated: *by default* no audio is written; the opt-in folder is listed in §6), `docs/ARCHITECTURE.md` (§3 STT row, §4 data on disk, §9 row COPILOT-17, filter/exam-follow-up note), `CLAUDE.md` (latest task → COPILOT-17), `docs/decisions/ADR-0001-stack.md` untouched (no new dependency; a note in the handoff that cloud STT stays excluded by D3) |

## Risks
| Risk | Mitigation |
|---|---|
| The script filter blocks Latin, so English IT terms in a uk/ru question are lost or transliterated | AC-02 measures it before the feature is considered done; one flag to switch the hint off; the term-sentence check through `LanguageGate`; owner sees it in H-1. Honest note: the hint does not separate uk from ru, so a Ukrainian question can still come out in Russian (known, not claimed fixed) |
| COPILOT-16 `LanguageGate` relied on English phrases arriving as Latin text | With the hint, foreign speech may become Cyrillic noise instead of English and bypass the gate; AC-02(c) and H-1 check; no change to the gate in this task |
| Opener list is too eager: a real follow-up starting with «що таке…» opens a new ticket | Start-anchored only; follow-up cases in R-04 eval; the owner can still continue the old ticket from the panel (existing behavior); list tuned on the eval, not guessed |
| Whisper text replaces a good root with a worse one | Guards in R-05 (non-empty, not hallucination, ticket unchanged); the update is logged with sizes; reversible only by the next turn — accepted, Whisper uk was correct on all synthetic and live checks of the diagnosis |
| +2.2 s makes the hint late in a live exam | Setting visible with its cost in the label, `off` is one tap, default only for exam + uk; R-07 timeout falls back to Parakeet |
| Saved audio contains other people's voices and the owner's own speech picked up on the call channel | Opt-in, off by default, plain wording in the settings, 600/700 permissions, backup exclusion, retention, wipe with history, never in repo/logs, interviewer channel only |
| Audio saving blocks or slows the pipeline | Background queue after the turn is delivered; failures ignored; measured in AC-06 |
| `AGENTS.md` says "No audio is ever written to disk" | R-11 rewrites it to "by default"; the opt-in is documented in §6 |
