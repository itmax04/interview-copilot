## Что сделать
Реализуй plan.md по шагам, начиная с первого незавершённого в handoff.md, до P-11 включительно.
Итог — `dist/InterviewCopilot.app` с улучшениями Parakeet и `docs/changes/COPILOT-02/report.md` со свидетельствами
по AC-01…AC-12.

## Как работать
- Один шаг P-xx за раз. После шага:
  1. проверки шага из plan.md;
  2. просмотр своего diff (лишние файлы, секреты, личные данные, случайное форматирование);
  3. обновление handoff.md;
  4. коммит `P-xx: <что сделано>`;
  5. `git push origin feat/copilot-02`.
- Вопросы владельцу — только в точках H-0…H-3. В точке H: остановись, дай пошаговую инструкцию на русском,
  скажи, что проверишь после ответа, жди «готово».
- Неоднозначность вне точек H решай сам в порядке приоритета: spec → ADR-0001 → документация FluidAudio 0.17.7
  (`.build/checkouts/FluidAudio/Documentation/ASR/`) → техническая целесообразность. Решение записывай в handoff.md →
  «Решения исполнителя» со ссылкой на R-/AC-.
- Поведение FluidAudio проверяй по исходникам версии 0.17.7 в `.build/checkouts`, не по памяти.
- Сравнения точности делай на одинаковом звуке: один и тот же набор, одна сборка, одна папка моделей.

## Границы
- Разрешено:
  - писать код, тесты, скрипты и синтетические фикстуры в репозитории;
  - запускать приложение, тестовый звонок, evals и замеры памяти;
  - скачивать модели из ADR-0001 с проверкой SHA256; Parakeet CTC 110M — только если Q3 = да;
  - коммитить и пушить в `feat/copilot-02`.
- Запрещено:
  - force-push, `reset --hard`, удаление веток, переписывание истории, merge в `main` или `feat/copilot-01`;
  - менять TCC, Keychain trust и системные настройки;
  - портить или удалять оригинальную папку моделей и профиль владельца (опыты — на копии через
    `INTERVIEWCOPILOT_MODELS_DIR` / `INTERVIEWCOPILOT_HOME`);
  - коммитить `profile/`, модели, логи, записи голоса владельца, FLEURS;
  - писать текст реплик в логи;
  - облачное распознавание, платные сервисы, обновление FluidAudio;
  - публиковать что-либо.
- Не ослабляй тесты и пороги evals ради зелёного результата. Не пиши «проверено» без фактического запуска команды.
- Новая зависимость или модель вне ADR-0001 — только с записью в ADR и пометкой «требует подтверждения владельца при приёмке».

## Когда остановиться и эскалировать
Условия — plan.md, раздел «Условия остановки». При остановке:
- сохрани состояние в handoff.md (сделано, гипотезы, следующий шаг);
- закоммить и запушь рабочее состояние, если оно собирается;
- опиши владельцу проблему и варианты.
