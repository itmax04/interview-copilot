# COPILOT-02: Спецификация — точность Parakeet v3

ID: COPILOT-02-spec · Статус: **draft** · Версия: 1 · Дата: 2026-10-22 · Владелец: itmax04
Связи: [intent.md](intent.md) (цель, границы, вопросы Q1–Q6) · [plan.md](plan.md) (реализация) ·
[ADR-0001](../../decisions/ADR-0001-stack.md) · [COPILOT-01 spec](../COPILOT-01/spec.md) · [evals/README.md](../../../evals/README.md)
Единственный источник требований этой задачи — этот файл. Номера R-/S-/AC- без префикса относятся к COPILOT-02;
требования прошлой задачи пишутся с префиксом: «01/R-04», «01/AC-05». Требования COPILOT-01 продолжают действовать.

## 1. Термины
- **Фраза (реплика)** — речь собеседника между паузами VAD (01/R-03); итоговый текст фразы — **итог** (final).
- **Длинная фраза** — фраза, звук которой при распознавании итога длиннее 15 с (больше одного окна Parakeet).
- **Стык (шов)** — место, где FluidAudio склеивает результаты соседних окон по 15 с.
- **Словарь терминов** — список канонических написаний (`Kubernetes`, `PostgreSQL`, `CI/CD`) и их вариантов,
  собранный по R-03.
- **Поправка** — замена фрагмента итога каноническим термином из словаря.
- **Raw WER** — доля ошибок по словам, как в report.md COPILOT-01 v0.1.2: расстояние редактирования по словам,
  без регистра и пунктуации, ё = е, апострофы нормализованы, числа в исходном написании.
- **Baseline v0.1.2** — тестовый звонок 2026-10-08, 15 фраз, Parakeet v3: RU 7/96 (7,29%), UK 9/97 (9,28%),
  EN 4/123 (3,25%), медиана задержки итога 501 мс.

## 2. Сценарии
- **S-01. Длинный вопрос.** Дано: движок Parakeet, источник — Chrome. Когда: собеседник 20 с говорит без пауз ≥ 350 мс
  и замолкает. Тогда: в панели один итог без пропуска, повтора или «склейки» слов на стыке; язык текста не меняется
  посреди фразы.
- **S-02. Термин из базы.** Дано: в `questions.yaml` есть «PostgreSQL». Когда: собеседник говорит
  «Как вы оптимизировали запросы в PostgreSQL?», а модель распознала «постгрес кьюэль». Тогда: в итоге «PostgreSQL».
- **S-03. Похожее обычное слово.** Дано: в словаре есть «Jira». Когда: собеседник говорит «жира в этом блюде много».
  Тогда: поправки нет (слово не заменяется без достаточного сходства и контекста по R-04).
- **S-04. Шум без речи.** Когда: в звуке созвона клавиатура, музыка или шорох без речи, VAD открыл фразу.
  Тогда: итог с одним-двумя словами и низкой уверенностью не показывается и не запускает поиск по базе.
- **S-05. Сбой Parakeet.** Дано: в папке Parakeet нет одного файла из манифеста или Core ML не загрузил модель.
  Когда: начинается слушание. Тогда: загружается Whisper из настроек, статус —
  «Parakeet не загрузился: <причина>. Используется Whisper <модель>».
- **S-06. Явный английский.** Дано: Language = English, движок Parakeet. Когда: звучит английский вопрос
  на сжатом звуке. Тогда: в итоге нет кириллических букв.
- **S-07. Явный украинский или русский.** Дано: Language = Українська или Русский, движок Parakeet.
  Тогда: текст распознаётся как в Auto (английские термины сохраняются латиницей), а в меню Language и в Settings → Audio
  видна подпись, что для Parakeet выбор UK/RU задаёт только метку языка.

## 3. Требования

### Длинные фразы
- **R-01. Набор длинных фраз.**
  - ≥ 9 синтетических фраз длиной 18–25 с: по 3 на uk/ru/en; в каждой ≥ 1 английский технический термин или число.
  - Для каждой — чистый вариант и вариант «сжатый звук звонка» (как `*-long-compressed`): AAC 8 кГц ~12 кбит/с → WAV 16 кГц моно.
  - Эталонный текст — в `Resources/TestCall/clips.json` (тестовый звонок) и в манифесте для `scripts/eval-local-stt.py`.
  - Фикстуры создаются воспроизводимым скриптом из репозитория (сейчас скрипта для `evals/audio/test-call/` нет),
    голоса как в 01/P-04: uk — Lesya, ru — Milena, en — Samantha.
  - Прогон двумя путями: напрямую в движок (`copilot-eval stt-parakeet`, без VAD) и через тестовый звонок
    (захват Chrome → VAD → StreamingTranscriber). Длина звука каждого итога (`audio_ms`) записывается в результаты.
- **R-02. Защита стыков.** Если по R-01 WER длинных фраз выше порога AC-02 или найдены ошибки на стыке
  (пропуск ≥ 2 слов подряд, повтор, слово с чужим алфавитом), включить защиту и выбрать вариант по замеру:
  1. `ASRConfig.dualDecodeArbitration = true` (FluidAudio, путь v3 no-mel);
  2. своя нарезка итога на куски ≤ 15 с по точке минимальной энергии в окне 10–15 с, с объединением текста.

  Выбор, замеры и стоимость по времени записываются в ADR-0001. Если ошибок на стыках нет — защита не включается,
  факт записывается в ADR-0001 и report.md.

### Словарь терминов
- **R-03. Источник словаря** (решение Q1):
  - автоматически из `profile/questions.yaml`: слова латиницей внутри кириллических формулировок, аббревиатуры
    (≥ 2 заглавные буквы), слова с внутренними заглавными (`JavaScript`), смешанные с цифрами (`S3`, `K8s`);
  - необязательный `profile/vocabulary.yaml`:
    ```yaml
    - term: PostgreSQL           # каноническое написание
      variants: [постгрес, постгрескуэль, postgres sql]   # необязательно
    ```
  - словарь перестраивается при сохранении `questions.yaml` или `vocabulary.yaml` (как 01/S-10);
    ошибка разбора `vocabulary.yaml` показывается в меню, остаётся прежний словарь;
  - пример — `profile.example/vocabulary.yaml` (синтетический).
- **R-04. Поправка итога.**
  - Применяется к итоговому тексту обоих движков до передачи в определение хода и поиск по базе; промежуточный текст
    не меняется (A-2).
  - Сопоставление: явные варианты из `vocabulary.yaml` — точное совпадение без учёта регистра; остальные — нечёткое
    по транслитерации и расстоянию редактирования (можно использовать BK-дерево FluidAudio `CustomVocabulary/BKTree`
    или своё). Порог сходства подбирается по набору AC-04 и записывается в evals/README.
  - Заменяются только фрагменты длиной 1–3 слова; слово из списка частых слов языка (стоп-лист) без явного варианта
    не заменяется (S-03).
  - Отключается в Settings → Audio («Исправлять термины по базе», по умолчанию включено).
  - В лог — только число поправок на итог, без текста (01/R-24).
- **R-05. CTC-усиление словаря — исследование** (только при Q3 = да).
  - FluidAudio Custom Vocabulary, Approach 2: отдельный кодировщик Parakeet CTC 110M (≈ 97,5 МБ на диске,
    +64–130 МБ памяти по документации FluidAudio).
  - Проверить на наборе AC-04: помогает ли на кириллице или только на английских терминах в кириллической фразе;
    память (AC-10) и задержку (AC-09).
  - Итог — запись в ADR-0001 «принять / отклонить» с цифрами. По умолчанию выключено; включение — решение владельца.
  - Модель загружается из официального репозитория FluidInference с SHA256 в манифесте (как `parakeet-models.json`).

### Фильтр шума
- **R-06. Отсев мусорных итогов.** Итог Parakeet не выдаётся, если одновременно: ≤ 2 слова и
  `confidence` (средняя вероятность токенов FluidAudio) ниже порога C. Порог C подбирается на наборе шума и
  на коротких репликах набора `turn`, записывается в evals/README. Для Whisper действующий фильтр
  `noSpeechProbability` не меняется. Определение хода (01/R-05) уже требует ≥ 3 слов, поэтому реплики из 1–2 слов
  на ответ не влияют; фильтр убирает их из панели и истории.

### Надёжность движка
- **R-07. Проверка установки и переход на Whisper.**
  - Parakeet считается установленным, только если все файлы из `parakeet-models.json` есть и их размеры совпадают
    (SHA256 проверяет установщик; при запуске — только наличие и размер, чтобы не замедлять старт).
  - Любая ошибка загрузки Parakeet → загрузка Whisper из `whisperModel` по S-05. Нет и Whisper — текущая ошибка
    «Нет модели распознавания».
  - Переход не меняет сохранённую настройку движка: при следующем запуске снова пробуется Parakeet.

### Язык
- **R-08. Фильтр алфавита.** При Language = English и движке Parakeet вызов `AsrManager.transcribe` получает
  `language: .english` (фильтр алфавита FluidAudio, `TokenLanguageFilter`). При Auto, Українська, Русский фильтр
  не передаётся: он не различает uk и ru и выбросил бы английские термины.
- **R-09. Честные подписи.** Для движка Parakeet в подменю Language и в Settings → Audio — подпись:
  «Parakeet определяет язык сам; UK/RU меняют только метку языка, English убирает кириллицу».
  Рекомендация «выберите язык в меню» в документации (test-plan, report) уточняется: относится к Whisper.
- **R-10. Закрепление языка только для Whisper.** Логика `stickyLanguage` / `sessionLanguage` / `lowConfidenceStreak`
  в `StreamingTranscriber` не выполняется для движков с `nativeMultilingual = true`. Поведение Whisper не меняется
  (существующие тесты `StreamingTranscriberTests` проходят без правок ожиданий).

### Качество и проверки
- **R-11. Усиление тихого звука.** Сравнить Parakeet с `WhisperEngine.normalized` и без него на тихих и сжатых
  фразах (R-01 + `*-long-quiet`, `*-long-compressed`). Оставить вариант с меньшим raw WER; при равенстве (± 1 ошибка
  на язык) — без усиления. Решение в ADR-0001.
- **R-12. Тесты адаптера.** Swift Testing для `ParakeetEngine`, выполняются только при установленной модели
  (иначе пропуск с причиной, не провал):
  - тишина −80 dBFS, 2 с → пустой текст без вызова модели;
  - `cancel()` во время распознавания 20-секундного файла → возврат ошибки отмены быстрее, чем полное распознавание;
  - метка языка для uk/ru/en фикстур;
  - файл длиннее 15 с → непустой текст;
  - English + `language: .english` → в тексте нет кириллицы.

  Юнит-тесты без модели: словарь (R-03, R-04), фильтр (R-06), проверка манифеста и переход (R-07), выбор фильтра
  языка (R-08), отключение sticky-логики (R-10).
- **R-13. Неизменное.** Аудио на диск не пишется (01/R-04); облачное распознавание не используется;
  `ModelHub.offlineMode = true`; новые фикстуры — только синтетические; файлы владельца и FLEURS — вне Git.

## 4. Критерии приёмки
| AC | Критерий | Способ проверки |
|---|---|---|
| AC-01 | Набор длинных фраз есть: ≥ 9 фраз 18–25 с (3 на язык) × 2 варианта звука, эталоны в `clips.json` и манифесте, скрипт генерации в `scripts/` | Список файлов и длительностей (`afinfo`) в report.md; повторный запуск скрипта даёт те же длительности ± 0,1 с |
| AC-02 | Длинные фразы, Parakeet, прямой прогон: raw WER по языку ≤ baseline v0.1.2 + 3 п. п. (RU ≤ 10,3%, UK ≤ 12,3%, EN ≤ 6,3%); ни одного пропуска ≥ 3 слов подряд | `scripts/eval-local-stt.py` на манифесте R-01, таблица по языкам и вариантам звука |
| AC-03 | Регрессии нет: 15 фраз v0.1.2 через тестовый звонок — ошибок не больше baseline + 1 на язык (RU ≤ 8, UK ≤ 10, EN ≤ 5) | Тестовый звонок, JSON-отчёт страницы |
| AC-04 | Термины: на наборе ≥ 15 фраз с терминами (≥ 5 на язык) доля верно записанных терминов ≥ 80%, а ошибок в терминах как минимум вдвое меньше, чем на том же наборе без поправок; на контрольном наборе ≥ 30 фраз без терминов — 0 ложных поправок | Новый eval `vocab` (`copilot-eval vocab` или режим `eval-local-stt.py`), baseline — тот же набор без поправок |
| AC-05 | Шум: на наборе ≥ 20 синтетических записей без речи (клавиатура, музыка, шорох, тишина с щелчками, 5–10 с) показано ≤ 1 итога; на 15 фразах v0.1.2 не потеряно ни одной | Тестовый звонок или `copilot-eval stt-stream` по набору шума; число итогов в report.md |
| AC-06 | Переход на Whisper: при удалённом файле из манифеста Parakeet приложение слушает с Whisper и показывает статус по S-05 | Юнит-тест проверки манифеста + ручная проверка исполнителем на копии папки моделей (оригинал владельца не трогать) |
| AC-07 | English: на 5 EN фразах тестового звонка с Language = English в итогах 0 кириллических букв; при Українська / Русский текст совпадает с Auto | Тестовый звонок с выбранным языком + юнит-тест выбора фильтра |
| AC-08 | Подписи R-09 видны в меню Language и в Settings → Audio при Parakeet | Скриншоты в `docs/changes/COPILOT-02/evidence/` |
| AC-09 | Задержка: медиана «конец фразы → итог» ≤ 1 с на 15 фразах v0.1.2 и ≤ 1,5 с на длинных фразах (с поправками и фильтром) | `scripts/metrics.py` по логам тестового звонка |
| AC-10 | Память: максимум `footprint` ≤ 1,5 ГБ за 10 минут со слушанием и распознаванием (Parakeet + bge-m3; + CTC, если принят) | `scripts/footprint-monitor.sh 10` во время повторяющегося тестового звонка |
| AC-11 | Сборка и проверки: `swift build`, `swift test` (все прежние 157 + новые), `scripts/run-evals.sh` (bank и turn — прежние пороги), `scripts/secret-scan.sh` 0 findings, `scripts/build-app.sh` + `codesign --verify --strict`, чистый клон | Команды и вывод в report.md |
| AC-12 | Решения задокументированы: ADR-0001 (стыки, усиление, CTC), evals/README (пороги C и сходства, новые наборы), report.md COPILOT-02 со статусом каждого AC | Просмотр документов при H-3 |

Пороги AC-02, AC-04, AC-05 — предложение (Q2). Если baseline P-00/P-01 покажет, что порог недостижим или тривиален,
исполнитель останавливается у H-1 с цифрами и предложением, а не меняет порог сам.
