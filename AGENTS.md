# AGENTS.md — onboarding for AI agents and developers

This is the entry point to the repository. Read it first: it explains what the app does, how the code is organized, how
to build, run and verify it, and how to make changes safely. Deeper references are linked at the end of each section.

> **Short version.** Native macOS app (Swift 6, SwiftUI + AppKit, SwiftPM, no `.xcodeproj`). Logic lives in
> `Sources/CopilotCore` (unit-tested, no UI), the app target `Sources/InterviewCopilot` only wires things together and
> draws the UI. Verify every change with
> `swift test && scripts/run-evals.sh && scripts/secret-scan.sh && scripts/check-localization.sh && scripts/build-app.sh`.
> Never put API keys or personal data in code, logs, tests, commits or messages.

---

## 1. What the app is

**Interview Copilot** is a personal macOS menu-bar app with a floating overlay. During a live call (Google Meet in a
browser, Zoom, Telegram) it:

1. captures the other person's audio (ScreenCaptureKit, audio of one app) and, separately, the owner's microphone;
2. transcribes speech **locally** — Parakeet v3 (FluidAudio, Core ML) as the main engine, Whisper (whisper.cpp) as an
   alternative and for refining the final text; languages: Ukrainian, Russian, English;
3. filters out noise, foreign-language chatter, other voices, echo and recognition hallucinations;
4. detects the end of a question (a *turn*);
5. shows an answer within about one second: a card from the owner's prepared question bank, or a hint generated by a
   chain of LLM providers (Groq → Cerebras → Gemini → DeepSeek → Claude → a custom OpenAI-compatible API), streamed;
6. remembers the whole interview (questions, the owner's spoken answers, shown hints) and reviews it after the call.

Other features: sessions created in a wizard (call type, profile, job posting, source, language, model, pre-start
check), multiple candidate profiles (résumé, facts, job, instructions, study materials, question bank with prepared
answers), screenshot → coding-task solution by a strong model, answer style (format/length/tone), post-call review and
"Ask AI", a local AI mock interview (the model asks questions by voice), a browser-based test call for measuring
recognition accuracy, light/dark theme, Russian/English UI.

There is exactly one user — the **owner**. The app is not distributed. No audio is ever written to disk.

Current version: see `CFBundleShortVersionString` in `Resources/Info.plist` and the latest task in `docs/changes/`.

## 2. Working agreements (must follow)

These come from `CLAUDE.md`; they are binding for agents.

- **Secrets and personal data.** API keys live only in the macOS Keychain. Never write keys, résumés, transcripts or
  other personal data into code, logs, tests, commits, docs or chat. Test data is synthetic only (`profile.example/`,
  `evals/`). Run `scripts/secret-scan.sh` before every push.
- **Git.** One task = one branch `feat/copilot-NN-<short-name>` created from the previous task's branch. Commit after every
  step. Push only when the owner has allowed it. **Forbidden:** force-push, `reset --hard`, deleting branches, rewriting
  history, merging into `main` without the owner's decision. Branch names, commit messages, PR texts and docs are in
  **English**.
- **Language with the owner.** The owner speaks Russian: answer the owner in Russian. Repository documents are English.
- **Dependencies.** Only those listed in `docs/decisions/ADR-0001-stack.md`; anything new needs an ADR entry and a note
  in the task handoff. Downloaded models are verified by SHA256.
- **System settings.** Do not change TCC (privacy permissions) or Keychain trust — the owner does that by hand.
- **Questions to the owner** only at the `H-…` checkpoints of the current task plan; resolve other ambiguities yourself
  (spec, design, Apple HIG) and record the decision in the handoff under "Executor decisions".
- **Done means** the acceptance criteria (AC) of the current spec are backed by evidence in its `handoff.md`, unverified
  items are listed, and the owner accepted the result.

## 3. Requirements and setup

| Item | Requirement |
|---|---|
| Hardware / OS | Apple Silicon Mac, macOS 15 or newer (developed on an M1 with 8 GB RAM) |
| Toolchain | Xcode 26+ selected with `sudo xcode-select -s /Applications/Xcode.app` (tests need Xcode, not only the CLT) |
| Code signing | A self-signed "Code Signing" certificate named `InterviewCopilot` or `InterviewCopilot Dev` in the login keychain (stable signature = Keychain and TCC permissions survive rebuilds) |
| Disk | ≥ 3 GB for models |
| API keys | Groq and/or Gemini (free tiers) are enough; Cerebras, DeepSeek, Anthropic, custom API are optional. Keys are entered in the app (Settings → Model keys) and stored in the Keychain |

First-time setup:

```bash
scripts/fetch-parakeet.py       # Parakeet v3 (pinned revision, SHA256)
scripts/fetch-models.sh         # Whisper + bge-m3 embeddings (SHA256) — the onboarding wizard can do this too
scripts/fetch-filter-models.py  # Silero VAD, CAM++ voiceprint, LocalVQE
scripts/build-app.sh            # release build, bundle and sign dist/InterviewCopilot.app
open dist/InterviewCopilot.app  # parrot icon in the menu bar; main window opens
```

On first launch the onboarding wizard asks for permissions (Screen & System Audio Recording, Microphone — granted by
the owner in System Settings), a free Groq key and the models. Launch flags: `--settings`, `--profile`, `--test-call`,
`--ai-interview`.

## 5. Architecture in one page

```
call app audio ─► SystemAudioCapture ─► AudioRingBuffer (30 s) ─► StreamingTranscriber ──┐
owner mic ─► MicActivityDetector (is the owner speaking) ─► TurnDetector                   │
          └► second StreamingTranscriber (owner answers) ─► InterviewMemory.addAnswer      │
                                                                                           ▼
StreamingTranscriber: EnergyVAD segments → Silero "is it speech" → Parakeet final (~0.1 s) → HallucinationFilter →
  voiceprint (mic mode) → events .partial / .final / .revised (Whisper turbo refine) / .foreignVoice / .discarded
                                                                                           ▼
ListeningController: language filter (LanguageGate + term dictionary) → transcript line or a gray "filtered" line
                                                                                           ▼
TurnController → TurnDetector: pause T (700 ms; 350 ms after "?"), owner speech, echo → Turn
  + speculative draft request for a finished phrase before the pause expires
                                                                                           ▼
AppDelegate.turnCompleted → InterviewMemory.addQuestion → AnswerController.handle(turn)
  BankController.lookup (one bge-m3 embedding: bank cards + material chunks) → AnswerRouter (mode) →
  bank card | PromptBuilder (profile, instructions, <materials>, history) → ProviderChain (SSE streaming,
  key rotation, hedging, fallback, last resort) → AnswerHistory (question → versions) → PanelModel → PanelView
                                                                                           ▼
hint → InterviewMemory.setHint; everything → SessionController → SessionStore (JSON, retention) → ReviewController
```

Threading: the main actor owns UI and controllers. Recognition, embeddings, Keychain reads and networking run off the
main thread (`Task.detached`, transcriber queues). Cross-thread state uses small lock-protected boxes
(`TranscriberBox`, `VoiceGateBox`, `AudioRouteBox`, …).

**Rule:** logic goes into `CopilotCore` (testable without UI); `InterviewCopilot` wires callbacks and renders.

### Key components

| Area | Where | What to know |
|---|---|---|

## 7. Conventions

- **UI text.** Write UI strings in Russian, as one literal (never `"…" + "…"`, it cannot be translated). SwiftUI literals are
  translated automatically; strings built in code use `L("…")` (app) or `L10n.t` / `L10n.f` (Core). Add the English line
  to `Resources/en.lproj/Localizable.strings`; `scripts/check-localization.sh` fails on missing keys or mismatched
  format specifiers. New windows: wrap the root view in `.localizedRoot()` and set the title with
  `UILanguage.shared.setTitle(_:of:)`. Text the owner reads from the AI (review, "Ask AI") follows the UI language
  (`L10n.aiLanguageName`); live hints follow the interviewer's language.
- **Design.** Window colors only via `IC` tokens (light/dark); the overlay is always dark (`ICDark`). System animations,
  respect Reduce Motion. Sources: Apple HIG and the redesign references in `docs/design/redesign/prompts.md`.
  The owner's global web-frontend rules (21st.dev, DESIGN.md, …) do **not** apply to this native app.
- **Logging.** `Log.<category>` (`audio`, `stt`, `turns`, `llm`, `metrics`, `app`). Log events, numbers and model IDs only —
  never utterance text, answers or keys. Provider error messages are passed through `SSE.redactIdentifiers`.
- **Persistence compatibility.** New fields in stored JSON (`SessionRecord`, settings) must be optional or decoded with
  `decodeIfPresent` / defaults: old files must keep loading.
- **Comments.** Source comments are mostly Russian (the owner's language) and reference requirement IDs such as
  `COPILOT-09 R-08`; look the ID up in `docs/changes/COPILOT-09/spec.md`. New comments may be English or Russian; keep
  them short and about *why*.
- **Tests** use Swift Testing (`@Suite`, `@Test`, `#expect`). Global language state in tests: use
  `L10n.$scope.withValue(...)`, never mutate `L10n.language` (tests run in parallel).

## 8. How to make common changes

| Change | Steps |
|---|---|
| A rule for the model | Edit `PromptBuilder.system`/`user`; add a unit test asserting the rule text; if it changes model behavior, add a scenario to `CopilotCore/Memory/PromptScenarios.swift` and run `--smoke-memory` from the signed app (uses free quota). Update the scenario count in `InterviewMemoryTests`. |
| An LLM provider | `ProviderID` + `ProviderEndpoints` + an `LLMProvider` implementation (SSE) + `ChainFactory.providers` + `AppSettings.chain` migration + `KeyVerifier`; add stream fixtures to `Tests/CopilotCoreTests/Fixtures/`. Set `acceptsImages` if it cannot take screenshots. |
| A setting | Field in `AppSettings` (decode with a default, clamp in `normalized()`), UI in `InterviewCopilot/Settings/`, reaction in `AppDelegate.applySettings`. |
| A hotkey | Append a `HotkeyAction` **at the end** of `allCases` (raw value = index), default in `HotkeyBinding.defaults`, handle in `AppDelegate.handle(_: HotkeyAction)`; show it in UI via `hotkey(_:)`, not a literal. |
| A menu item | `MenuAction` + `MenuLayout.sections` + `AppDelegate.handle(_: MenuAction)` (the switch is exhaustive) + `MenuLayoutTests`. |
| A UI string or window | See §7 "UI text"; run `scripts/check-localization.sh`. |
| Provider fallback behavior | `ProviderChain` (`run` sequential, `runHedged` parallel, `lastResort`), `ProviderHealth`; tests in `ChainResilienceTests`, `MultiKeyTests`, `LLMTests`. |
| Something stored on disk | Keep it backward compatible (optional fields), keep permissions 600/700, never store audio. |
| A dependency or model | ADR entry in `docs/decisions/ADR-0001-stack.md`; models with SHA256 in the lists at the repo root. |

## 10. Debugging

```bash
/usr/bin/log show --predicate 'subsystem == "com.itmax04.interviewcopilot"' --info --last 30m
```

Categories `audio`, `stt`, `turns`, `llm`, `metrics`, `app`. Useful events: `transcript_final`, `transcript_revised`,
`filtered reason=lang|vad|voice|echo|hallucination`, `turn_end`, `draft_start/used/cancelled`, `bank_match`, `no_match`,
`first_token … ms_from_speech_end=…`, `not_a_question`, `provider … failed: …`, `last resort: …`, `capture_restart`.
Session files in `sessions/*.json` contain per-turn `source`, `model`, `firstTokenMs`, `inputTokens` — useful for
latency and quota analysis (do not copy their text anywhere).

## 11. Task process and history

Every change is a task `COPILOT-NN` with a folder in `docs/changes/`:
`intent.md` (problem, owner decisions) → `spec.md` (requirements `R-…`, acceptance criteria `AC-…`) → `plan.md`
(steps `P-…`, owner checkpoints `H-…`) → `handoff.md` (what was done, commits, checks PASS/FAIL/NOT RUN, executor
decisions, next step). Read the latest task's handoff before starting.

Branches form a chain (each task branches from the previous one). `main` is fast-forwarded to the latest reviewed task
by the owner's decision. Task index: `docs/ARCHITECTURE.md` §9.

## 12. Known limitations and pitfalls

- Free Groq keys allow ~8 000 tokens per minute and a hint request is ~6 000 tokens, so one key serves about one hint per
  minute; add keys or rely on the fallback chain. Shrinking materials/instructions also helps.
- Ukrainian recognition is the main source of transcript errors; the Whisper refine pass occasionally makes a phrase worse.
- Model answers are probabilistic: prompt rules are verified by `--smoke-memory`, not guaranteed. One trap scenario
  ("you mentioned Kafka", garbled ASR) passes 14/15 since the "have you worked with X" rule.
- No acoustic echo cancellation: echo is removed by the voiceprint and a timing rule.
- ScreenCaptureKit may ignore "hide from screen capture" on macOS 15+; the overlay offers an honest visibility check.
- Global hotkeys use Carbon; the ⌘-scheme is registered only during a session and can conflict with other apps.
- There is no CI: the full check above is run locally (it needs Xcode 26, model files and a signing identity).

## 13. Glossary

| Term | Meaning |
|---|---|
| Owner | The single user of the app |
| Turn | A completed question from the other side, produced by `TurnDetector` |
| Hint | A generated answer shown in the overlay |
| Bank / card | The owner's prepared questions with answers (`questions.yaml`) |
| Profile | Résumé, facts, job, instructions, materials and questions for one job search |
| Session | A call from Start to End; nothing is captured outside a session |
| Chain | The ordered list of LLM providers/keys tried for an answer |
| Hedge | A parallel request to another provider after `hedgeAfter` seconds of silence |
| Last resort | Waiting for a key's rate limit to reset instead of failing |
| Review | Post-call comments, summary and "Ask AI" |
| `R-…`, `AC-…`, `P-…`, `H-…` | Requirement, acceptance criterion, plan step, owner checkpoint IDs in task docs |
