# Инструкции проекта Interview Copilot

## Проект
Нативное приложение macOS на Swift 6 (SwiftUI + AppKit), сборка через SwiftPM без .xcodeproj.
Сначала прочитать `docs/ARCHITECTURE.md` (поток данных, модули, типичные изменения, проверки, журнал).
Карта, команды и ограничения — `README.md`. Стек и причины — `docs/decisions/ADR-0001-stack.md`.
Задачи — `docs/changes/COPILOT-NN/` (intent → spec → plan → handoff); последняя — с наибольшим номером (сейчас COPILOT-07).

## Проверки
- Быстрая: `swift build && swift test`
- Полная: `swift test && scripts/run-evals.sh && scripts/secret-scan.sh && scripts/build-app.sh`
- Команды появляются по шагам plan.md; если команда ещё не существует — так и пиши (NOT RUN), не выдумывай результат.

## Правила
- Отвечать владельцу по-русски.
- Ключи API и личные данные (резюме, расшифровки) не писать в код, логи, тесты, коммиты и сообщения.
  Тестовые данные — только синтетические, из `profile.example/` и `evals/`.
- Новая задача — своя ветка `feat/copilot-NN-<кратко>` от ветки предыдущей задачи. После каждого шага — коммит;
  `git push` — когда владелец разрешил отправку.
  Запрещено: force-push, `reset --hard`, удаление веток, переписывание истории, merge в `main` без решения владельца.
- Новые зависимости — только перечисленные в ADR-0001; любая другая требует записи в ADR и отметки в handoff.
- Модели и загрузки: разрешено скачивать модели whisper/эмбеддингов и ставить зависимости через SwiftPM/Homebrew.
  Скачанные файлы проверять по SHA256.
- Не трогать системные настройки безопасности и приватности (TCC, Keychain trust): это делает владелец по инструкции.
- Вопросы владельцу — только в точках H-… из plan.md текущей задачи. Остальные неоднозначности решать самостоятельно
  по spec, дизайну и Apple HIG, решение записывать в handoff.md («Решения исполнителя»).
- После каждого шага обновлять `handoff.md` текущей задачи: сделано, коммит, проверки (PASS/FAIL/NOT RUN), следующий шаг.

## Дизайн
- Источник: `docs/design/menu-v2.webp` + раздел «Интерфейс» в spec.md (отклонения от картинки перечислены там).
- Глобальные правила фронтенда владельца (21st.dev, component.gallery, Kinetics, DESIGN.md) относятся к вебу
  и к этому нативному проекту не применяются — источник стиля здесь Apple HIG + картинки. Решение владельца от 2026-10-06.
- Анимации: системные; учитывать «Уменьшить движение» (`accessibilityReduceMotion`).

## Готово, когда
Критерии AC из spec.md текущей задачи подтверждены свидетельствами в её handoff.md (или report.md),
непроверенное перечислено, владелец принял результат.
